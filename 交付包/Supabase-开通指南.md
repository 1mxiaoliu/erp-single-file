# Supabase 免费云同步 · 开通指南

> **目标**：手机、电脑、平板共用同一份账目，随时随地能开单，一分钱不花，不装任何软件。  
> **耗时**：20 分钟（其中 10 分钟是等它初始化）。  
> **说明**：整套东西只用一个 Supabase 账号——数据库和网页都放在里面。

---

## 开工前先看这一段（很重要，能省你半小时）

很多人以为"填个地址就能同步"，结果卡在一个地方：**网页是从哪打开的**。

| 打开方式                               | 能不能连 Supabase | 原因                                   |
| ---------------------------------- | ------------- | ------------------------------------ |
| 双击本地 `进销存ERP.html`（地址栏是 `file://`） | ❌ **一定不行**    | 程序里直接禁用了：本地文件没有"域名"，浏览器不给它存会话，同步无从谈起 |
| 局域网 `http://192.168.x.x:8080`      | ✅ 可以          | 但出门就用不了                              |
| **`https://` 开头的网址**               | ✅ **最佳**      | 手机电脑随时能开，不需要任何设备常开                   |

**所以第 4 步「把网页放上互联网」不能跳过。** 传完你会得到一个 `https://` 网址，这才是客户每天打开的东西。

整个方案要注册**两个**免费账号：

| 账号             | 干什么用        | 能不能省          |
| -------------- | ----------- | ------------- |
| **Supabase**   | 存数据（数据库）    | 不能            |
| **Cloudflare** | 放网页（让它变成网址） | 能用 Netlify 代替 |

> 别想只用 Supabase 一个：它明确禁止用 Storage 托管 HTML 页面（打开只会看到代码）。原因见第 4 步开头。

## 第 1 步：注册并建项目（5 分钟 + 等 2 分钟）

1. 浏览器打开 **<https://supabase.com>** → 右上角 **Start your project**
2. 用 **GitHub 账号**登录（最快），或者邮箱注册
3. 进入控制台后点 **New project**，填：
   | 栏位                | 填什么                                        |
   | ----------------- | ------------------------------------------ |
   | Organization      | 默认那个就行                                     |
   | Name              | `erp`                                      |
   | Database Password | 随便设一个**强密码**，记在备忘录里（这套同步其实用不到它，但以后要进数据库会用） |
   | Region            | **Southeast Asia (Singapore)** ← 选这个，离国内最近 |
   | Plan              | Free                                       |
4. 点 **Create new project**，等 1～2 分钟初始化完成（页面会转圈）。

> 免费额度：数据库 500MB、流量 5GB/月、API 请求不限、最多 2 个免费项目。  
> 进销存的账目是纯文字，一个月几十 KB，**够用很多年**。

---

## 第 2 步：建表（2 分钟）

1. 左侧**最外面那一条竖排图标**里，找到 **`>_`** 形状的那个（SQL Editor），点它
2. 点 **New query**
3. 打开交付包里的 **`Supabase建表.sql`**，**全选复制**，粘贴进编辑框
4. 点右下角 **Run**（或按 Ctrl/Cmd + Enter）

看到 **`Success. No rows returned`** 就成功了。

> 想确认一下：把 SQL 文件最后那两行 `-- select ...` 前面的 `--` 删掉，再 Run 一次。  
> 应该返回 1 行，`id = main`，`ver = 0`，`doc_size` 几十字节。

**常见的报错**：

| 报错                                         | 意思           | 怎么办           |
| ------------------------------------------ | ------------ | ------------- |
| `relation "public.erp_doc" already exists` | 表已经建过了       | 不用管，继续下一步     |
| `must be owner of table`                   | 你用的不是项目所有者账号 | 退出重登，用建项目那个账号 |

## 第 3 步：拿两个值（1 分钟）

> ⚠️ **新版 Supabase 把这两样东西分开放了，很多人卡在这一步。**  
> 你现在如果停在 `Settings → API Keys` 页面，那里**只有 key，没有 URL**。

### 3.1 先拿 Project URL

地址的格式是固定的：**`https://项目ID.supabase.co`**

**项目 ID 就在你的浏览器地址栏里**，看一眼：

```
https://supabase.com/dashboard/project/abcdefghijklmnop/settings/general
                                     └──── 这一段就是项目 ID ────┘
```

拼起来就是：

```
https://abcdefghijklmnop.supabase.co
```

省得找。如果你还是想从界面上复制，三个地方能看到：

| 位置                       | 说明                                         |
| ------------------------ | ------------------------------------------ |
| `Settings → Data API`    | 新版把 URL 挪到这里了，General 里有时看不到               |
| 右上角 `Connect` 按钮 → 弹窗最底部 | `NEXT_PUBLIC_SUPABASE_URL=` 后面那一串（注意别带变量名） |
| 项目首页 `Project Overview`  | 顶部也会显示                                     |

**验证拼出来的地址对不对**：浏览器直接打开下面这个（把项目 ID 换成你的）：

```
https://你的项目ID.supabase.co/rest/v1/erp_doc?select=id
```

- 看到 `{"message":"No API key found in request"}` → ✅ **地址对了**（缺 key 是正常的）
- 看到 `{"code":"PGRST205"...}` 或 `table not found` → 地址对，但第 2 步的表还没建
- 打不开 / 找不到服务器 → 项目 ID 抄错了

### 3.2 再拿 key

在 `Settings → API Keys` 页面，注意顶部有**两个标签**：

| 标签                                   | 里面是什么                                                                           | 建议           |
| ------------------------------------ | ------------------------------------------------------------------------------- | ------------ |
| `Publishable and secret API keys`    | 新版 key，`sb_publishable_...` 开头。**新建的项目这里可能是空的**，要先点 `+ New publishable key` 建一个 | 可以用          |
| `Legacy anon, service_role API keys` | 老版 key，`eyJhbGci...` 开头。**已经有现成的，不用创建**                                         | ✅ **推荐，少一步** |

**最省事**：点第二个标签 **`Legacy anon, service_role API keys`**，复制 `anon` / `public` 那一长串。

⚠️ 同一页还有一个 `service_role`（新版叫 secret key），那是**管理员钥匙，绝对不要复制**。  
它无视所有安全策略，泄露等于把整个数据库交出去。

> 两种 key 我们的网页都认，你用哪个都行，只要**所有设备填的是同一个**。

把 URL 和 key 一起粘到记事本里，第 5 步每台设备都要用。

## 第 4 步：把网页放上互联网（3 分钟）

> ### ⛔ 先排除一个坑：不要用 Supabase Storage 放网页
>
> Supabase 官方文档里有一句：**"出于安全考虑，HTML 文件以纯文本形式返回"**。  
> 意思是，你把 `index.html` 传进 Storage，打开只会看到一屏代码（像记事本），**永远不会变成页面**。  
> 这是它防钓鱼的设计，改 public、换 key、换文件名都绕不过去。
>
> **数据库用 Supabase，网页用 Cloudflare Pages。** 这是最省事的组合。
>
> ### ⛔ 第二个坑：不要建 Worker，要建 Pages
>
> Cloudflare 的新界面把 Worker 和 Page**s 合在了一起，点 Create 很容易一路建出个 Worker，  
> 拿到 `xxx.workers.dev` 的网址——这个域名在国内打不开**（DNS 被污染，实测解析到无效地址），  
> 客户用手机 4G 一定白屏。
>
> `xxx.pages.dev` 是通的（实测可访问）。所以请认准 **Pages**，网址结尾是 **`.pages.dev`**。  
> 万一建成了 Worker，别慌，也不用删：回到 Workers & Pages 列表，重新点 Create 走一遍 Pages 就行。

### 你要上传的文件夹：已经在桌面准备好了

```
C:\Users\31787\Desktop\erp-web\
    ├── index.html              ← 账本本体（已改好名，别动）
    ├── manifest.webmanifest    ← 让手机能"添加到主屏幕"
    ├── sw.js                   ← 断网也能打开
    └── icon-180.png
        icon-192.png
        icon-512.png
```

**整个文件夹一起传**，不要拆开、不要改名、不要只传 html（少一个文件就装不成 App）。

### 操作

1. 打开 **<https://dash.cloudflare.com/sign-up>** 注册（邮箱 + 密码，去邮箱点验证链接）
2. 进控制台以后**不要找 "Workers & Pages"**（2026 年新版界面已经没有这个一级菜单了）。  
   直接点这个链接，一步到位：

   **<https://dash.cloudflare.com/?to=/:account/workers-and-pages>**

   或者手动点：左侧 **Build（构建）** → **Compute** → 里面就是 **Workers & Pages**

   想跳过列表直接新建 Pages，就点这个：

   **<https://dash.cloudflare.com/?to=/:account/pages/new>**
3. 点右上角 **Create** / **Create application**
4. 选 **Pages** 标签 → 点 **Upload assets**（有个上传图标那个）
5. 项目名填 **`erp`** → 点 **Create project**
6. 把桌面上的 **`erp-web` 文件夹整个拖进去**（或点按钮选文件夹）
7. 点 **Deploy site**

> 新版控制台把 Workers 和 Pages 合并成了一个叫 **Compute** 的列表，所以老教程里的 "Workers & Pages" 找不到是正常的，功能一个没少。

十几秒后，页面顶部会给你一个网址：

```
https://erp.pages.dev
```

也可能带随机后缀，比如 `https://erp-7xk.pages.dev` —— **以它显示的为准**。

**先看一眼网址结尾**：

| 结尾             | 能用吗         | 说明                      |
| -------------- | ----------- | ----------------------- |
| `.pages.dev`   | ✅ 就用这个      | 国内可访问                   |
| `.workers.dev` | ❌ **国内打不开** | 建成了 Worker，回列表重新建 Pages |

**这就是客户以后每天打开的网址。** 记下来。

> 拖文件夹时注意：要让 `index.html` 出现在**根目录**，不是 `erp-web/erp-web/index.html`。传完在文件列表里应该直接看到 `index.html`。

### 打开试一下

浏览器访问那个 `https://erp.pages.dev`，应该直接出现进销存界面。

| 现象      | 原因            | 怎么办                                 |
| ------- | ------------- | ----------------------------------- |
| 正常显示界面  | ✅ 成功          | 继续第 5 步                             |
| 打开是 404 | 文件层级错了        | 回 Pages 项目里看，`index.html` 必须在最外层    |
| 又看到一屏代码 | 你把 html 传到别处了 | 确认访问的是 `pages.dev`，不是 `supabase.co` |

## 第 5 步：每台设备填一次同步（每台 1 分钟）

在**刚拿到的那个网址**上（不是本地文件）：

1. 点左下角 **我的** → **关于存储** → **设置云同步**
2. 填两个值：
   | 栏位  | 填什么                                                                   |
   | --- | --------------------------------------------------------------------- |
   | 地址  | `https://abcdefghijkl.supabase.co`（只到 `.co`，**后面不要带 `/rest/v1` 或斜杠**） |
   | key | 第 3 步那个 key（`eyJ...` 的 anon，或 `sb_publishable_...` 都行）                |
3. 点保存，它会自动测试连接并上传第一版数据

看到右上角出现 **已自动保存 · 已同步** 就成了。

**然后每台设备都做一遍**：手机、店里电脑、家里电脑，打开同一个网址，填同样两个值。

> 手机上强烈建议「添加到主屏幕」：iPhone 用 Safari 打开 → 分享 → 添加到主屏幕；安卓用 Chrome → 菜单 → 安装应用。  
> 用 Cloudflare Pages 托管时图标和离线功能都完整，加完就是一个独立 App 的样子。  
> ⚠️ 微信里打开的网页装不了，也连不稳，务必点右上角「…」→「在浏览器打开」。

> **定了网址就别换。** 浏览器是按"域名"分仓库的：从 `xxx.pages.dev` 换成别的域名，本机就是一个全新的空账本。  
> 真要换，先在旧地址「导出」，再到新地址「导入」，最后重新填一次云同步。

## 关于「7 天不用会被暂停」

Supabase 官方规则：**免费项目连续 7 天没有数据库活动，会被暂停**（paused）。

- **正常营业完全不会触发**：每天开单、开页面，请求远超过它的门槛
- **会被触发的场景**：连续一周完全没打开（比如长假、或者客户买来放着不用）
- **被暂停后**：网页会提示连不上 → 登录 supabase.com → 项目上点 **Resume project** → 一两分钟后恢复，**数据一条不少**（1 年内都能恢复）

### 怎么避免

| 做法      | 说明                                 |
| ------- | ---------------------------------- |
| 最省事     | 每周随便打开一次账本，看一眼就够                   |
| 想彻底不管   | 用 UptimeRobot（免费）每 3 天访问一次 API，见下面 |
| 花 $25/月 | 升 Pro，永不暂停（**没必要**）                |

**UptimeRobot 保活配置**（可选，5 分钟）：

1. 注册 uptimerobot.com（免费版 50 个监控）
2. Add New Monitor → 类型 **HTTP(s)**
3. URL 填：`https://你的项目.supabase.co/rest/v1/erp_doc?select=id`
4. 展开 **Custom HTTP Headers**，加两条：
   ```
   apikey: 你的 Publishable key
   Authorization: Bearer 你的 Publishable key
   ```
5. 监控间隔选 **每 3 天**（或 12 小时）

这样即使一直不用，项目也不会被暂停。

## 安全须知（请一定读）

**① anon / publishable key 的性质**

Supabase 设计上就允许这个 key 公开出现在前端，安全性靠的是数据库的"行级安全策略"（RLS）。

我们跑的 SQL 里，策略只允许它碰 **`erp_doc` 这一张表**，碰不到 Supabase 项目里的其他任何东西。这一点是安全的。

但要注意：**拿到这个 key 的人，能读写你的账本**（商品、客户、价格、进货价）。

所以：

- ❌ 不要把带 key 的截图发到群里、教程里、朋友圈
- ❌ 不要把网址和 key 一起发给不相干的人
- ✅ 万一泄露了：Supabase → Project Settings → API Keys → 重新生成 publishable key → 所有设备重新填一次（旧 key 立刻失效）

**② 数据存在别人家的服务器上**

Supabase 是国外服务，数据实际存在 AWS 新加坡。传输是加密的，但**服务商在技术上能看到你的数据**。

如果你的账本里有特别敏感的东西（大客户名单、独家进货渠道），请在交付前跟客户说清楚这一句。介意的话，就选云主机方案（数据在国内、只有你自己能看）。

**③ 别把 `service_role` key 填进去**

那个 key 无视所有安全策略，泄露等于把整个数据库交出去。

## 备份（免费版有个坑）

⚠️ **Supabase 免费项目不能下载数据库备份**（官方限制，Pro 才有）。

两条路，任选：

**A. 让它自动备份（推荐，配一次就不用管）**
见 `自动备份/自动备份-说明.md`：用 GitHub 的免费定时任务，每天凌晨自动把整本账拉一份存进私有仓库，**不用任何电脑开机**，能回溯 180 天。

**B. 手动导出**
1. **我的 → 备份恢复 → 导出**，得到一个 `进销存备份_2026xxxx.json`
2. 存到电脑、网盘、微信收藏都行
3. 换电脑、换 Supabase 项目、误删数据，都用它恢复

**这条比省钱重要。** 交付时至少要当着客户的面做一次导出，让他知道文件长什么样。

> 差别：手动导出**带商品图片**（文件大）；自动备份只有数据、没有图片。
> 所以最稳的是 **A 常开 + 想起来手动导一次**。

## 以后要换服务器怎么办

| 场景            | 操作                                                 |
| ------------- | -------------------------------------------------- |
| 换 Supabase 项目 | 新项目跑一遍 SQL → 网页「设置云同步」填新地址和 key → 它会问是否上传本机数据 → 选是 |
| 想搬到自己的云主机     | 网页导出 JSON → 新服务器导入 → 把同步地址改成 `http://新IP:8080`     |
| 客户不用了         | Supabase 后台删项目即可，数据随之删除（先导出！）                      |

**数据始终是"整本账一个 JSON"**，不会被任何一家服务商锁死。这是当初选这个结构的原因。

---

## 最后：交付时要说清的三句话

1. **"每周至少打开一次"** —— 否则 7 天后云会被暂停（数据不丢，但要你去后台点一下恢复）
2. **"每月导出一次备份"** —— 免费版不能下载云端备份，那个 json 是唯一保险
3. **"两台同时改同一张单，以服务器那份为准"** —— 极少发生，但要知道
